# 我的路书 · 多用户版(建站包)

一个纯静态 PWA:`index.html` 一个文件包含全部界面与逻辑,配合腾讯云开发(CloudBase)做登录与路书存储,地图用高德 Web JS API。

## 文件

- `index.html` — 应用本体(登录、我的路书、总览地图、编辑器、分享、个人信息)
- `manifest.json` — PWA 清单(名称、图标、启动方式)
- `icon-180/192/512.png`、`favicon-32.png` — 图标

## 本地预览

任意静态服务器即可,例如:

```bash
python3 -m http.server 8080
# 浏览器打开 http://localhost:8080
```

不要用 `file://` 直接打开 —— manifest 和部分接口需要 http(s)。

## 部署到 GitHub Pages

1. 新建仓库(公开或私有均可,Pages 需要公开或付费计划)。
2. 把本目录内所有文件放到仓库根目录,推送到 `main`。
3. 仓库 Settings → Pages → Source 选 `Deploy from a branch`,Branch 选 `main` / `(root)`,保存。
4. 一两分钟后访问 `https://<用户名>.github.io/<仓库名>/`。
5. 手机 Safari 打开该网址 → 分享 → **添加到主屏幕**,即可像 App 一样全屏使用。

> 注意:部署在子路径时,`manifest.json` 里的 `start_url` / `scope` 用的是相对路径(`./`),无需改动。

## 上线前必做的两件事

1. **高德 key**:在高德开放平台申请 *Web 端(JS API)* key + 安全密钥,并在控制台把域名加入白名单。
2. **数据隔离**:在云开发控制台把路书集合的权限设为「仅创建者可读写」,否则默认规则可能允许他人读取你的行程与备注。分享链接依赖随机 token,请勿把 token 写进公开页面。

## 本次更新:广场 + 游记补完

这次改动把"我的路书 - 多用户版建站包 2.7"里已经做得比较完整的**独立游记模块**(时间轴/卡片以外的第三种沉淀——把路书某次拍一份图文快照,单独写、单独发)整体移植了进来,并且把手机端"广场"从一个只读的路书列表,扩展成了路书 + 游记两个子 tab 的公开内容广场。改完之后,桌面端和手机端(`#mshell`)都能用同一套逻辑。

### 界面结构的变化
- 新增两个桌面 `.app-screen`:`#screen-travelogue-list`(我的游记汇总列表)、`#screen-travelogue`(单篇游记的编辑器,左边选取内容/写字/传图,右边实时预览,导出 PDF / 小红书文案)。路书列表页新增「📝 我的游记」入口,每条路书的操作栏新增「📝」图标直接跳到这条路书下的游记。
- 手机端沿用给 `#screen-profile` 用的"浮层覆盖 `#mshell`,但留出底部 70px 给 Tab 栏"这个技巧,原样套用到这两个新屏幕上(`body.mobile-on #screen-travelogue-list.active` / `#screen-travelogue.active`),不用另写一套手机端的游记编辑 UI——点击底部「游记」Tab 进入的是一个新的仪表盘(当前路书的游记 / 我的全部游记 / 广场上的游记三个入口),真正的增删改查全部复用桌面那一套。
- 手机端「广场」Tab 从纯路书列表改成了"路书 / 游记"两个子 tab(`.plaza-tabs`),游记子 tab 点开是只读预览 + 「存一份到我的游记」。

### 数据 & 后端需要补的东西
- `roadbook` 和 `travelogues` 两张表都新增了一个**顶层布尔列** `is_public`(默认 `false`),不是塞进 `data` JSON 里的子字段——这样云开发控制台里"is_public=true 的行任何人可读"的行级权限规则可以直接配置,不强依赖云函数。
- 广场拉取数据时优先调用云函数 `list_shared_routes()` / `list_shared_travelogues()`(和旧版思路一致:全量查询 + 服务端按 `is_public` 过滤,绕开 JSON 子字段不能筛选的限制);如果云函数暂时没有部署或调用失败,前端会自动兜底改成直接按 `is_public` 列查询(`cbDb.from('roadbook').eq('is_public', true)...`)。两条路都留着,哪条能跑通就用哪条——**但兜底这条路要求后台把这两张表的 RLS 改成公开行任何人可读**,不然会一直空着。
- 「分享」弹窗里新增了「同时发布到路书广场」勾选框,勾上就是 `roadbook.is_public = true`;游记的「导出」面板里也有同样一个开关,对应 `travelogues.is_public`。两者都是独立开关,和原来基于 `share_token` 的私密链接分享互不影响、可以同时开着。
- 广场里点开一篇别人的公开游记是只读预览(不会污染自己的数据),「存一份到我的游记」会在 `travelogues` 表里插入一条新记录,`user_id` 换成当前用户、`route_id` 置空(因为对方的路书你并不拥有),不会覆盖或链接到别人的原始数据。

### 已知的简化 / 后续可以做得更好的地方
- 手机端游记编辑器目前直接复用桌面版的两栏布局并在窄屏下把右侧预览栏隐藏(`body.mobile-on #tl-preview-col{display:none}`),体验是可用但不够"原生手机感",如果要做成更贴合触屏的单栏卡片式编辑,需要单独设计。
- 广场"抄一份"路书走的还是原来的 `get_shared_route` 云函数(按 `share_token` 精确取一条,绕开 RLS),这要求公开路书本身也生成过 `share_token`——目前「发布到广场」和「生成分享链接」是分开两步(前者需要后者已经生成过 token 才能在广场里被别人一键抄走);如果希望"仅发布到广场"也能不点分享链接就直接抄一份,需要另外给 `list_shared_routes()` 之类的云函数加一个不依赖 token、直接按行 id 读取公开路书完整数据的接口。
